# Чеклист требований — Midterm Project (React SPA)

Источник: `react.Midterm Project.pdf` (единственный источник требований и рубрики).
Каждая строка проверяется вручную перед сдачей. Колонка «Где» заполняется по ходу работы.

## 1. Общие требования (раздел Requirements)

- [ ] R1. Один источник данных — собственный simulated API (Promise + задержка + JSON + `localStorage`).
- [ ] R2. Не менее 100 начальных записей в основном списке (план: 180).
- [ ] R3. Не менее 5 осмысленных переиспользуемых компонентов (план: 8+).
- [ ] R4. Есть список (list view) и детальная страница (detail view).
- [ ] R5. Controlled-форма добавления нового элемента.
- [ ] R6. Осмысленные поиск, фильтрация, сортировка и пагинация.
- [ ] R7. `useState` и `useEffect` используются корректно.
- [ ] R8. Обработаны состояния loading, error, empty, success.
- [ ] R9. Корректные зависимости эффектов и cleanup там, где он нужен.
- [ ] R10. Стабильные keys и корректная работа с идентичностью компонентов.
- [ ] R11. Нет прямой манипуляции DOM.
- [ ] R12. Чистый, единообразный, адаптивный и удобный UI.
- [ ] R13. Приложение готово к деплою и работает с публичной ссылки (деплой выполняет владелец).
- [ ] R14. Индивидуальный, уникальный проект (не шаблонный todo/weather).

## 2. Рубрика — исходный код (6 баллов)

### 2.1 React Architecture & Rendering — 1 балл
- [ ] A1. Приложение разделено на осмысленные переиспользуемые компоненты.
- [ ] A2. Props и композиция компонентов используются корректно.
- [ ] A3. JSX и условный рендеринг чистые и понятные.
- [ ] A4. Списки используют корректные стабильные keys.
- [ ] A5. Идентичность компонентов и сохранение/сброс состояния обработаны там, где это важно.

### 2.2 State, Events & Forms — 1.5 балла
- [ ] S1. `useState` используется уместно для состояния приложения и UI.
- [ ] S2. Обрабатывается несколько осмысленных событий.
- [ ] S3. Controlled inputs и формы реализованы корректно.
- [ ] S4. Состояние обновляется иммутабельно.
- [ ] S5. Состояние размещено в подходящих компонентах, а не всё в `App`.
- [ ] S6. Нет ненужной прямой манипуляции DOM.

### 2.3 UI & Consistency — 1.5 балла
- [ ] U1. У приложения понятное назначение и единая тема.
- [ ] U2. UI чистый, адаптивный и аккуратно стилизован (360 / 768 / 1280 px).
- [ ] U3. Нет сломанных, незаконченных, placeholder- или лишних элементов UI.
- [ ] U4. Цельный пользовательский опыт, а не набор несвязанных React-примеров.

### 2.4 API & Deployment — 2 балла
- [ ] D1. Данные API осмысленно интегрированы (не просто «загрузили и показали»).
- [ ] D2. `useEffect` и массивы зависимостей используются корректно.
- [ ] D3. Реализованы состояния loading, error, empty, success.
- [ ] D4. Эффекты используют cleanup, где это необходимо.
- [ ] D5. Обработаны устаревшие асинхронные обновления и race conditions.
- [ ] D6. Поиск, фильтрация, сортировка и пагинация корректно работают с источником данных.
- [ ] D7. Репозиторий организован, есть понятный `README`.
- [ ] D8. Задеплоенное приложение полностью работоспособно (сборка готова; деплой — владелец).
- [ ] D9. Деплой обязателен (иначе 0 за раздел) — подготовлена инструкция для владельца.
- [ ] D10. В simulated API не меньше 100 начальных записей (иначе штраф).
